# 추가 안전성 보완 — 2026-11-06

이 기록은 REMEDIATION-2026-11-06.md 이후의 추가 점검·수정 내용이다. 실제 메일 발송, Google 로그인, 외부 공개는 수행하지 않았다.

## 발견하고 수정한 문제

1. **발송 요청이 끝나지 않을 수 있음**
   - Gmail 요청에 60초 제한과 AbortController를 추가했다.
   - 요청 또는 응답 읽기 실패는 ‘결과 불명’으로 처리한다. 시간 초과가 메일 미발송을 보장하지 않으므로 보낸메일함 확인을 안내한다.
   - 자동 재시도는 하지 않는다.

2. **같은 메일의 즉시 재발송**
   - 현재 페이지의 최근 20개 발송 비교 결과를 SHA-256 해시로만 임시 보관한다.
   - 같은 작성 내용·수신 정보·선택된 첨부가 이미 발송되었거나 결과가 불명확하면, 보낸메일함을 확인하고 다시 보내겠다는 별도 체크가 필요하다.
   - 새로고침, 다른 탭, 다른 파일 재선택 등에 걸친 전체 중복을 보장하는 기능은 아니다.
   - 기록을 브라우저 저장소나 서버에 남기지 않는다.

3. **인증이 취소되어도 연결된 것으로 표시될 수 있음**
   - 401 응답을 받으면 메모리 토큰과 연결 상태를 제거하고 재연결을 안내한다.
   - Google 준비 스크립트 15초, 권한 연결 120초 제한을 두었다.
   - 연결 작업 중 페이지를 벗어난 뒤 늦게 도착한 응답이 연결 상태를 복구하지 않도록 세대 값을 확인한다.
   - 권한 연결의 늦은 콜백·승인 거절·팝업 실패는 성공으로 처리하지 않는다.

4. **불완전한 응답을 성공으로 표시할 가능성**
   - 성공 HTTP 상태와 비어 있지 않은 문자열 메시지 ID가 모두 있어야 발송 확인으로 표시한다.
   - 잘못된 JSON, ID 누락·잘못된 타입, 네트워크 단절, 서버 오류를 구분했다.
   - Google의 오류 본문·토큰·메일 내용을 사용자 로그에 출력하지 않는다.
   - 발송 fetch에는 credentials:omit, cache:no-store를 적용했다.

5. **첨부·본문·주소 한도 부족**
   - 첨부 합계 18MiB 제한에 더해 최대 30개 및 비어 있거나 크기가 잘못된 파일을 검사한다.
   - 메일 본문은 UTF-8 기준 512KiB, 수신자·CC·BCC는 합계 50명으로 제한한다.
   - 화면 검증 외에 실제 MIME 생성 직전에도 같은 한도를 확인한다.
   - 주소의 점 위치, 연속된 점, 로컬 부분·도메인 라벨 길이, 헤더 제어 문자를 검사한다.
   - 국제화 주소·따옴표 형식 주소를 모두 지원하는 RFC 전체 파서는 아니며, 일반적인 ASCII 이메일 주소를 지원한다.

6. **긴 한글 첨부파일명과 여러 주소의 MIME 줄 길이**
   - 파일명은 RFC2231 형태의 연속 매개변수로 나눠 인코딩한다.
   - 여러 CC/BCC는 접힌 헤더로 작성한다.
   - 긴 한글·이모지 파일명 복원 및 MIME 줄 길이 검사를 통과했다.

7. **제목 편집이 본문 자동 갱신까지 중지시킴**
   - 제목과 본문의 직접 편집 상태를 분리했다.
   - 제목만 수정하면 본문은 신고 내용과 함께 계속 갱신된다.
   - 본문 직접 수정 후 신고 또는 첨부가 변경되면 경고하고 발송 전 별도 반영 확인을 요구한다.
   - 직접 수정한 본문을 임의로 덮어쓰지는 않는다.

8. **이미지 미리보기 실패와 키보드 사용성**
   - 이미지 미리보기는 lazy/async 방식으로 표시하고, 읽을 수 없으면 대체 표시를 제공한다. 원본 첨부를 자동 삭제하지 않는다.
   - 실패 상태에서 ARIA 이름을 사용할 수 있는 img 역할을 제공하도록 HTML 오류를 수정했다.
   - 1KiB보다 작은 자료는 바이트 단위로 표시하여 0 KB로 오해하지 않도록 했다.
   - 새 신고 추가 후 새 fieldset으로 포커스를 이동하고, 처리 상태를 live region에 안내한다.
   - 발송 중 상태도 열린 확인창 안에서 안내한다.

## 검증 결과

- 정적 빌드 성공, Vitest 32개 통과.
- 전체 npm audit: 알려진 취약점 0 (점검 시점).
- 외부 fetch를 전부 모의 객체로 대체한 단위 테스트로 성공·잘못된 ID·401·403·429·503·네트워크 실패·60초 제한·권한 콜백 시간 초과를 검사했다.
- 실제 브라우저와 분리된 테스트 컨텍스트에서만 Google 클라이언트를 모의 객체로 대체했다. 실제 외부 서비스로 나가는 요청은 허용하지 않았다.
- 해당 컨텍스트에서 성공 모의 응답, 401 모의 응답, 네트워크 실패 모의 응답 3회만 가로챘고, 자동 재시도가 없음을 확인했다.
- 동일 메일 재발송 확인, 결과 불명 후 재발송 확인, 수동 본문 변경 확인을 건너뛸 수 없음을 확인했다.
- 제목만 수정해도 본문이 갱신되는 점, 수동 본문 보존, 31개 첨부 거절·빈 파일 거절을 확인했다.
- 320/390/768/1440px 기본 배치 가로 넘침 없음.
- 손상 이미지 상태 및 최종 확인 상태의 선택한 WCAG/베스트 프랙티스 자동 위반 0.
- 손상 이미지 상태의 HTML standard 검사 오류 0. 최종 확인창도 이름 있는 dialog로 인식됨.
- 초기 화면의 장식 화살표 대비에는 자동 수동확인 항목 1개가 남는다. 기존 색상 대비를 수동 확인했으며 오류 0과 완전한 인증은 다르다.
- 입력·첨부·최종 확인 과정 외부 전송 0, localStorage/sessionStorage/IndexedDB/쿠키 비어 있음을 확인했다.
- Google 실제 송수신·실기기·실제 스크린리더·운영 호스팅 설정의 한계는 이전 보고서와 같다.
